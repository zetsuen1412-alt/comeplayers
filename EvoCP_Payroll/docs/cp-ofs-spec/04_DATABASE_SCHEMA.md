# Database Schema — Final Integrated V2

This document defines the target logical schema. Codex must first audit existing ComePlayers tables and **extend/reuse** compatible structures rather than blindly creating duplicates.

## A. Global conventions

- Primary key: UUID (`gen_random_uuid()` or repository-standard equivalent).
- Tenant data: `organization_id uuid not null`.
- Display/business code: separate indexed human identifier generated by a concurrency-safe sequence/function; never `MAX()+1`.
- Money: `BIGINT ..._minor`, positive unless the domain explicitly uses signed movement.
- Currency: ISO 4217 code.
- Quantity: `NUMERIC(30,8)`.
- Rates/FX: exact `NUMERIC`, not float.
- Percent: basis points integer.
- Timestamp: `TIMESTAMPTZ`; finance also stores `business_date DATE`.
- Mutable operational rows: `version integer` optimistic lock.
- Financial final rows: state-protected/append-only.
- Prefer `TEXT + CHECK` or lookup tables for evolving business statuses; avoid overusing PostgreSQL ENUM during active evolution.
- RLS default-deny.

## U. Database enforcement priorities

Constraints/triggers/functions must protect:

- allocation/completion limits;
- payment overmatching;
- outstanding repayment limits;
- posted-journal immutability;
- balanced posting;
- closed-period mutation rejection;
- audit append-only behavior;
- inventory movement idempotency and negative-stock policy;
- exactly-one fulfillment source;
- organization consistency across linked records;
- self-approval rules where policy requires separation of duties.

Aggregate invariants that cannot be expressed with a row CHECK must be enforced inside locking transaction functions/services, not assumed safe from frontend validation.
