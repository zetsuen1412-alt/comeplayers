# Chat onboarding UX — 28 September 2026

## Delivered behavior

- Sign-in opens the inbox without an automatic full-screen recovery modal. Community, marketplace and profile remain reachable.
- An unprepared private conversation shows inline setup with one primary action, Indonesian copy and an optional explanation. The conversation back button stays available.
- Already verified devices continue to open automatically. Existing encrypted accounts always recover their existing identity; the UI never creates a replacement identity to bypass recovery.
- Setup can also be completed inside account recovery and backup settings, avoiding disabled controls with no way forward.
- Cancellation is neutral and never automatically reopens the system prompt. Double taps and screen remounts share an in-flight activation. A failed enrollment request retries the prepared passkey.
- New passkeys display the signed-in email in the password manager. The stable cryptographic user handle, relying-party ID, synced-passkey validation and PIN/biometric verification are unchanged. Previously created passkeys keep their existing provider labels.
- Buttons expose accessible labels and busy/disabled states.

## Delivery

This is a JavaScript-only Android update compatible with the installed 0.15.0 native runtime. Native permissions, cryptographic protocol, server recovery policy and database schema are unchanged. Publication details are recorded after the update service confirms the release.

A passkey-free first conversation would require a separate design for device enrollment and recovery. This release does not silently remove recovery protection or promise that Google alone can restore encrypted history.
